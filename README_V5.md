# المنارة الطلابية — V5 (نسخة الحماية)

هذه النسخة تُصلح ثغرة دخول لوحة الإدارة، وثغرة XSS مخزّنة، ومشكلة فواصل الأسطر
في المنشورات، وتضيف نظام إشعارات دخول كامل.

---

## ⚠️ خطوة إلزامية قبل أي شيء

ارفع قواعد قاعدة البيانات الجديدة، وإلا لن يعمل سجل الدخول:

**Firebase Console → Realtime Database → Rules** → الصق محتوى `database.rules.json` → **Publish**.

---

## 1) ثغرة الدخول قبل تسجيل الدخول — أُصلحت

### ما كانت المشكلة

البوابة كانت **CSS فقط**. واجهة الإدارة كاملة كانت موجودة داخل `admin/index.html`،
وملف `v4-overrides.css` يخفيها بـ `visibility:hidden`.

يعني أي واحد من هؤلاء كان يكفي لتجاوزها:

- تأخّر تحميل ملف الـ CSS أو فشله → اللوحة تظهر وتشتغل.
- حذف `#admin-gate` من أدوات المطور (زر واحد) → اللوحة تظهر.
- كتابة `IS_ADMIN = true` في الكونسول → وضع التعديل يُفتح.
- `isEditMode` كان مفعّلاً تلقائياً بمجرد فتح `/admin/` قبل أي تحقق.

### الحل

الواجهة لم تعد موجودة في الصفحة إطلاقاً قبل التحقق. هي داخل
`<template id="admin-shell">`، ومحتوى الـ `<template>` **ليس جزءاً من الصفحة**
— لا يُصيَّر، ولا تصل إليه `querySelector`، ولا يُنفَّذ.

لا تُحقن إلا بعد أن يمرّ الحساب بكل هذه الشروط:

1. الدخول عبر Google فعلياً (`providerData` يحتوي `google.com`).
2. `emailVerified === true`.
3. توكن **حديث** مُجدَّد إجبارياً (`getIdToken(true)`) — لا اعتماد على توكن قديم.
4. الحساب هو المالك، أو له سجل في `adminUsers/{uid}`.
5. الجلسة لم تتغير أثناء التحقق (حماية من تبديل الحساب في منتصف العملية).

وحتى لو زوّر أحدهم المتغيرات، `canWriteData()` تشترط `ADMIN_VERIFIED === true`
الذي لا يُضبط إلا من داخل مسار التحقق، وقواعد Firebase ترفض الكتابة على الخادم
كطبقة ثانية مستقلة.

### حماية إضافية للجلسة

- **الجلسة تنتهي بإغلاق التبويب** (`Persistence.SESSION`).
- **قفل تلقائي بعد 20 دقيقة خمول.**
- **حد أقصى للجلسة 8 ساعات** مهما كان النشاط.
- **مراقبة لحظية للصلاحية**: لو سحبتَ صلاحية مشرف وهو داخل اللوحة، تُقفل عنده فوراً.
- **تجديد التوكن كل دقيقتين** — أي خلل يُنهي الجلسة.
- منع فتح اللوحة داخل `iframe`.

## 2) ثغرة XSS مخزّنة — أُصلحت (لم تكن في قائمتك، وهي الأخطر)

كان محتوى المنشورات يُحقن في `innerHTML` بدون تهريب في **55 موضعاً**:

```js
<p>${item.content}</p>        // قبل
<div>${esc(item.content)}</div>  // بعد
```

بما أن `appData` مقروء للعامة، كان يكفي حفظ خبر واحد يحتوي
`<img src=x onerror="...">` لينفّذ الكود عند **كل زائر** يفتح الموقع.

ما تم:

- تهريب كل محتوى المستخدم قبل عرضه.
- `safeUrl()` تمنع `javascript:` و `vbscript:` و `data:` الخطرة (بما فيها
  `data:image/svg+xml` التي تستطيع تنفيذ سكربت)، وتسمح فقط بـ
  `http/https/mailto/tel/sms/whatsapp` وصور base64 الآمنة.
- `jsAttr()` لتهريب النصوص الموضوعة داخل `onclick="..."`.
- صور المرفقات لم تعد تُمرَّر كـ base64 كامل داخل السمة، بل بالفهرس.
- `rel="noopener noreferrer"` على كل الروابط الخارجية.
- سياسة `Content-Security-Policy` على الصفحتين.

## 3) مشكلة الأسطر في المنشورات — أُصلحت

السبب: المحتوى يُعرض داخل HTML، و HTML يبتلع فواصل الأسطر ويحوّلها لمسافة واحدة.
لهذا كانت المقالة تطلع ملزوقة رغم أنك نزلت أسطراً في التعديل.

الحل: صنف `.rich-text` مع `white-space: pre-wrap` مطبَّق على:
محتوى الأخبار، الواجبات، الاختبارات، ملاحظات الحصص، نبذة أعضاء الفريق،
أسماء الدروس، وعناوين الروابط والملفات.

كذلك تحويل حقول التعديل القصيرة (الواجبات والاختبارات) من `<input>` إلى
`<textarea>` حتى تستطيع كتابة أسطر متعددة أصلاً.

## 4) إشعارات الدخول — نظام جديد بالكامل

### قبل

`accessLogs` كان يسجّل **أول دخول فقط** لكل حساب، بدون جهاز، بدون تكرار.
يعني لو دخل نفس الحساب مئة مرة من عشرة أجهزة، تشوف سطراً واحداً.

### الآن

كل محاولة دخول تُسجَّل في `loginEvents/{uid}/{eventId}` — **الناجحة والمرفوضة**:

| الحقل | المحتوى |
|---|---|
| `email` / `displayName` | حساب Google |
| `ts` | وقت الدخول بالثانية |
| `allowed` / `role` | مسموح / مرفوض، ومالك أم مشرف |
| `device` | هاتف / جهاز لوحي / كمبيوتر |
| `os` | Windows / Android / iOS / macOS / Linux |
| `browser` | Chrome / Safari / Firefox / Edge / Samsung |
| `screen` / `timezone` / `language` | تفاصيل إضافية |
| `ua` | البصمة التقنية الكاملة (مطوية) |

**العرض** في قسم «🔔 إشعارات الدخول»:

- مجمّع حسب اليوم: **اليوم** / **أمس** / التاريخ الكامل بالعربي.
- داخل كل يوم مرتّب من الأحدث للأقدم مع الساعة والدقيقة والثانية.
- عدّاد لكل يوم: كم دخول مسموح وكم محاولة مرفوضة.
- المحاولات المرفوضة بخلفية حمراء — هكذا تعرف لو حاول أحدهم الدخول.
- شارة **«جديد»** على ما لم تره بعد، وعدّاد أحمر على عنصر القائمة الجانبية.
- فلترة بالحساب، وزر تحديث، وزر حذف السجل (للمالك فقط).
- السجل القديم من `accessLogs` يُدمج تلقائياً في العرض حتى لا تفقد شيئاً.

> المشرف العادي يرى سجله فقط. المالك يرى الجميع.

## 5) إصلاحات في «ميكانيك النظام»

| المشكلة | الحالة |
|---|---|
| `getSubjectsList()` مستدعاة في 6 مواضع لكنها **غير معرّفة إطلاقاً** — قوائم اختيار المادة في الواجبات والاختبارات والتسجيلات والتقدم كانت معطّلة | عُرِّفت |
| `downloadAttachment('exam', …)` لم يكن لها فرع — تحميل مرفقات الاختبارات لا يعمل | أُصلح |
| `canWriteData()` كانت ترجع `true` على صفحة الزائر (منطق معكوس) | أُصلح |
| Service Worker كان `cache-first` لكل شيء **بما فيه `/admin/`** — نسخة مخبّأة من لوحة التحكم، والتحديثات لا تصل للمستخدمين | أُعيدت كتابته |
| انهيار الصفحة لو غاب أي عنصر (`current-date`, `page-heading`, `install-btn`) | حُصِّنت |
| لا حدّ لحجم البيانات المرسلة | حدّ 8MB مع رسالة واضحة |

## 6) اختبر بعد الرفع

1. افتح `/admin/` في نافذة خاصة. اضغط **F12 → Elements**، احذف `#admin-gate`.
   → لن تجد أي شريط جانبي ولا حقل تعديل. الصفحة فارغة تماماً.
2. في الكونسول اكتب `IS_ADMIN = true` ثم `canWriteData()` → `false`.
3. جرّب حساب Google ليس المالك → رسالة رفض، **وتظهر المحاولة في سجلك**.
4. ادخل بحساب المالك → افتح «إشعارات الدخول» وستجد دخولك مع جهازك ومتصفحك.
5. انشر خبراً واترك سطرين فارغين بينهما → افتح الموقع العام، الأسطر كما كتبتها.
6. انشر خبراً محتواه `<b>تجربة</b>` → يجب أن يظهر النص كما هو لا أن يصير عريضاً
   (هذا دليل أن التهريب يعمل).
7. اتركها 20 دقيقة بدون لمس → تُقفل تلقائياً.

## 7) ملاحظات

- **مفتاح `apiKey` في `firebase-config.js` ليس سراً** — هذا طبيعي في Firebase،
  وهو معرّف مشروع لا كلمة مرور. الحماية من `database.rules.json` ومن
  Authorized domains، وكلاهما مضبوط.
- للحماية القصوى فعّل **App Check** من Firebase Console، فيمنع استخدام قاعدة
  بياناتك من خارج موقعك.
- المالك ثابت في مكانين ويجب أن يتطابقا لو غيّرته:
  `assets/js/admin.js` (المتغير `OWNER_EMAIL`) و `database.rules.json`.
